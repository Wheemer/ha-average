## 🎉 Average Sensor v2.5.1

This release strengthens YAML migration, temperature calculations and recorded-history handling, with configurable limits for oversized or slow queries. It retains full UI configuration and the fork's additional calculation controls while keeping the `average` domain and existing sensor identities.

### ⬆️ Before updating

- **Home Assistant 2026.4.0 or newer is now required.**
- **History windows default to a maximum of 31 days.** For an existing longer average, increase **Advanced > Maximum history query window** or YAML `max_history_period`. Oversized windows become unavailable with an error; they are never silently shortened.
- **History queries have a 60-second wait limit by default.** Adjust **Advanced > History query timeout** or YAML `history_query_timeout` for a slower database. A timeout makes the sensor unavailable and allows a later retry; it cannot terminate SQL already running. Replacement queries wait for the existing query to finish.
- Keep existing YAML, names, unique IDs and entity IDs unchanged when updating. Active YAML remains supported. To switch to UI management, verify the imported settings, identity and history first, then comment out only that sensor's YAML definition. The integration never edits YAML files automatically.

### 🛠️ Fixes since v2.5.0

- **Protect YAML sensor identities.** Detect conflicting explicit unique IDs before importing, raise an actionable Repairs issue and refuse conflicting definitions without overwriting an existing entry. Multiple historical `__legacy__` definitions retain their separate identities.
- **Handle ambiguous edits safely.** When a no-ID YAML edit matches an existing imported sensor, Repairs explains how to add its existing unique ID and adopt the same entry. Intentionally separate same-name definitions remain supported with a warning. Completely changed names and sources cannot reliably be identified as edits; retain stable explicit IDs.
- **Apply YAML removals correctly.** Removing optional settings restores their defaults on reload while preserving the sensor's identity. Invalid imports show a useful reason, and UI creation rejects blank names.
- **Make temperature calculations independent of source order.** Refresh measurement metadata before reading values, clear stale temperature mode when metadata disappears and handle current values, recorded history and explicitly selected temperature attributes consistently.
- **Keep invalid numbers out of results.** Reject boolean, infinite and NaN fallback values in YAML and UI; discard invalid saved/restored values and nonfinite results. Normalize weighted contributions to avoid overflow and handle zero-decimal rounding safely.
- **Calculate sub-second windows correctly.** Preserve fractional timestamps throughout history weighting and caching, clamp weighting boundaries to the requested interval and reject nonpositive elapsed periods.
- **Recover when Recorder is unavailable.** Mark the average unavailable, avoid repeated warning storms and retry without consuming the successful-refresh interval.
- **Clean up refreshes during reload and shutdown.** Cancel and await refresh waiters with a bounded unload wait while retaining running SQL tracking across replacement entities. Failed or cancelled calculations clear stale values and partial diagnostics, and retries are not unnecessarily throttled.
- **Correct diagnostic attributes.** Undefined-value substitutions contribute to counts and extrema. Trend projections follow the configured precision, including existing negative precision settings.
- **Reduce repetitive logging.** Availability checks no longer consume conversion-error budgets. Repeated conversion failures, missing history and malformed boundaries are summarized or deduplicated while recovery continues. History/conversion logs avoid dumping complete source State objects.
- **Improve compatibility with Core internals.** Avoid overriding Home Assistant's internal state-calculation method and support the configuration-form APIs used by the minimum and current supported versions.

### ✨ Features available compared with upstream

- 🎛️ **Create and edit sensors in the UI**, including every calculation setting under **Configure > Advanced**, without a full Home Assistant restart for option changes.
- 📄 **Import existing YAML into UI entries** while retaining compatible legacy identities, with a Repairs notice explaining verification and optional YAML commenting. Continue using active YAML if preferred.
- ⚖️ **Weight individual sources** with optional nonnegative `weights`; equal weighting remains the default, and partial results adjust to usable contributors.
- 💧 **Choose a numeric attribute per source** with `source_attributes`, including attribute-only recorded changes. Recognized temperature, humidity, pressure and wind attributes carry supported measurement metadata. Non-temperature unit conversion is not automatic.
- 🚦 **Require every source** with `require_all_sources`, or retain partial averaging. Strict mode rejects missing, undefined, invalid or stale sources and waits for a complete recalculation after recovery.
- ⏱️ **Limit source age** with `max_source_age`, including expiry of quiet sources.
- 📊 **Control undefined history** with `ignore_undef`, `calculate_to_now_undef` and an optional numeric fallback. These controls do not override strict availability.
- 🛡️ **Configure history safety limits** through both YAML and UI using `max_history_period` and `history_query_timeout`.
- ⚡ **Keep large-history processing responsive** with executor-side decoding, cooperative calculation batches, reduced unnecessary attribute loading and protection against overlapping SQL during refreshes and reloads.
- 🏠 **Use local integration branding** with the complete house icon and transparent outer padding.

### 📦 Installation and maintenance

- Update this fork through its existing HACS or Marketplace repository. Manual installations extract **`average.zip`** into `config/custom_components/average/`; the release includes a SHA-256 checksum.
- Switching from the original YAML-only integration? Follow the [upgrade guide](https://github.com/Wheemer/ha-average/blob/v2.5.1/docs/upgrading.md). Finish installing the fork before restarting, keep `platform: average` unchanged and do not delete sensors under Devices & services. If the store says the integration is in use, cancel and follow the guide's restriction section.
- Refresh contribution, configuration and HACS information with maintained fork links and clearer migration guidance. Remove the unnecessary runtime pip dependency and synchronize release metadata without changing the independently maintained support minimum.
- Harden repository automation, security scanning and developer credential handling. Developer helpers now use environment/private-file credentials and Git's askpass pipe, with no tokens embedded in pip/git arguments or read from Home Assistant `secrets.yaml`.

Raw Recorder retention still limits available history. Long-term statistics are not queried automatically, completed-period caches do not automatically detect later backfills, and a timed-out SQL query still needs to finish or have its database problem resolved. See the [configuration reference](https://github.com/Wheemer/ha-average/blob/v2.5.1/docs/configuration.md) for settings and limitations.
